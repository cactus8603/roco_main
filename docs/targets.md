# Target features 的兩種製作方式

Target features 是修復模型的離線訓練目標。兩種製法都使用 GT 與完全凍結的 WAFT，
輸出可在相同位置接回 WAFT 的完整雙幀特徵。

| 項目 | 便宜版：非遮擋區 RGB 重建 | 昂貴版：直接最佳化特徵 |
|---|---|---|
| 調整對象 | 第一張影像中可見且有有效對應的 RGB | 每筆原始雙幀特徵的修正量 |
| 監督資訊 | GT 光流、有效像素與非遮擋標註 | GT 光流與原始有效像素 |
| 生成方式 | 重建 RGB 後經凍結特徵提取器 | 透過凍結 WAFT 最後輸出的 EPE 最佳化特徵 |
| 增量成本 | 已快取原始特徵時，額外編碼一張影像 | 可選 32、256、512 次特徵最佳化，預設 512 |
| 生成時反向傳播 | 無 | 有，只對特徵變量求導 |
| 特徵幅度限制 | 無 σ 投影 | 原始特徵周圍 ±0.25σ |
| 填補區域 | 保留重建影像經編碼得到的完整結果 | 保持原始特徵 bytes |

## 便宜版：重建非遮擋區 RGB

GT 描述第一張影像的像素 x 在第二張影像中的位置 x + g(x)。
對有效、有限、落在影像內且標註為非遮擋的對應，以第二張影像的顏色重建第一張：

```text
第一張重建影像(x) = 第二張影像(x + GT(x))   當對應有效、界內且非遮擋
第一張重建影像(x) = 第一張原始影像(x)     其他位置
```

使用 CPU FP64 bilinear interpolation，最後一次轉為 FP32；零位移也屬有效對應。
第二張 RGB 完整保留。
KITTI 的光流值來自 `flow_occ`，非遮擋支援來自 `flow_noc` 的 validity；
Sintel 則使用 `occlusions == 0`。
因此除了 GT 光流，此方法也需要非遮擋標註。

接著用原本凍結的 WAFT 特徵提取流程編碼重建後的第一張影像。
若已保存同一 teacher 影像對的原始特徵，就完整重用第二張特徵，額外只需一次單張編碼。
這個步驟不做 WAFT 光流迭代或最佳化；若要檢驗 target 品質，再另外執行完整光流評估。

Target 保留完整雙幀與全部填補區域，不裁切成 RGB 重建 mask。
即使某位置的 RGB 沒有被改動，編碼上下文仍可能使該處特徵改變。

### Sintel Final 的配對 Clean 規則

Final 的修復模型輸入仍由原 Final 影像提取。
其便宜 target 由**對應 Clean 的兩張影像**套用上述重建方法取得，
兩張 target features 與所有填補區域都使用完整 Clean 結果。
第二張特徵必須重用 Clean 的第二張，不能混入 Final 的第二張特徵。

製作前需核對配對、GT、有效像素、尺寸與填補幾何一致。
這項配對監督只在訓練資料準備時使用，推論不需要 Clean 影像。

## 昂貴版：直接最佳化特徵

從**原始輸入影像**的特徵開始，對每筆資料建立獨立修正量 δ：

```text
target = 原始特徵 + sigma × delta
```

σ 是原始雙幀特徵在原圖範圍的逐通道 RMS，以 FP64 reduction 計算，
floor 為 `0.01 × lower_median(channel_RMS) + 1e-8`。
只改動對應原圖的特徵中心，填補區域保持原始 bytes。
對 Sintel Final，起點是原 Final 特徵。

每次候選都在 hidden 初始化之前放回 WAFT，從零光流執行全部 5 次更新，
以第 5 次原尺寸光流對 GT 的向量 EPE 作為目標。
梯度穿過完整的光流回饋與取樣座標路徑，但 WAFT 權重完全不更新。

最佳化規則：

- δ 從零開始，依預先選定的預算固定做 32、256 或 512 次 AdamW 更新，預設 512，不 warmup、不提早停止。
- learning rate `0.001`、betas `(0.9, 0.999)`、epsilon `1e-8`、weight decay `0`；`foreach=False`、`fused=False`。
- 全域梯度 norm 與縮放使用 FP64，clip 為 `1`，分母加 `1e-6`，再複製回 FP32。
- 每次更新後將 δ 限制在 `[-0.25, 0.25]`，並將填補區域的 δ 歸零。
- 將原始起點與更新過程的全部候選納入比較，以 FP64 評分選出最早達到嚴格最低 EPE 的候選。
- 選中後再用無梯度的完整 5 次更新核對結果。

CLI 使用 `prepare --target expensive --target-steps 32`（也接受 256、512）；
Python API 使用 `expensive_target(..., steps=32)`。步數只控制外層特徵最佳化，
WAFT 內部更新次數始終為 5。候選包含 F0 與全部更新後的狀態，共「步數 + 1」個。
版本分別識別為 `waft-dense-final-epe-32-v1`、`waft-dense-final-epe-256-v1`、
`waft-dense-final-epe-512-v1`；封包記錄實際步數，不能將短步版本標成 512 步。
此選項不代表三種預算的 target 品質相同。

既有品質旗標要求 EPE 至少下降 20%、光流分量 MSE 嚴格下降，且原圖範圍的
正規化特徵變化非零；未通過者仍保存並列入統計。
旗標不代表所有樣本都能達標，也不改變便宜版按各資料集整體 mean EPE 檢驗的規則。

昂貴版的幅度限制屬於 target 製作配方；[修復模型](feature-repair.md)的輸出沒有此限制。

## 共同 WAFT 與評分規則

使用 Chairs+Things 訓練的 source-only WAFT，DAv2 特徵提取器與 vits 迭代模組，
全模型 **508 tensors／56,932,619 parameters** 保持 FP32、評估模式與權重凍結。
使用原始官方影像正規化、factor 112 填補及特徵融合流程。

EPE 評分始終使用原始有效 GT，包含遮擋與對應點落在影像外的像素。
便宜版的重建 mask 不會縮小評分分母。
各資料集報告逐影像平均 EPE，另保留有效像素 pooled EPE 與退步案例。

實際 API 與 checkpoint 核對方式見 [程式使用方式](usage.md)。
完整數值見 [結果與驗證範圍](results.md)。
